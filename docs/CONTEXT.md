# 领域术语表 · Bangumi 动画推荐系统

> 本文件**只是术语表**，不是规格说明、不是实现细节、不是需求文档。
> 代码与讨论中凡涉及以下术语，一律以此定义为准；出现歧义先改语言，不改定义。

## 核心实体

- **User** — 一个 Bangumi 用户，由 `username` 标识。存储时仅保留 username 的哈希。
- **Subject** — 一个条目（作品）。本系统只关注 `subject_type=2`（动画）。Subject 自带公开的聚合标签、评分、收藏数、排名等元数据。
- **CollectionEntry** — 用户对某个 Subject 的一条收藏记录，是系统的**原子数据单元**：
  `{ state, rate, tags, comment, updated_at }`。
- **Seed User** — 用于训练模型的用户群体。规模是可配置的（原型 1k → 发布 20k）。
- **Candidate** — 一次推荐请求中，待排序的"未收藏 Subject"集合。

## 状态与信号（容易混用的概念，重点厘清）

- **state（收藏状态）** — 用户对条目的态度，枚举：`想看 / 看过 / 在看 / 搁置 / 抛弃`。
  - `看过` 是最强的正信号。
  - `想看` 是意图信号，不是口味确认信号。
  - `抛弃` 是负信号，不进推荐候选池。
- **rate（评分）** — 用户给条目的打分，取值 `0~10`。**`rate=0` 表示"没打分"，与"打了 1 分"是两种完全不同的信号。**
- **显式评分（explicit rating）** — `rate>0` 的 CollectionEntry，用于相似度与数值预测。
- **隐式反馈（implicit feedback）** — "看过但未打分"的 CollectionEntry，用于隐式矩阵分解（如 ALS）。
- **收藏列表 vs 收藏行为** — "收藏列表"是 User 的一组 CollectionEntry；"收藏行为"是其中的单条记录。不要混用"收藏"二字指代两者。

## 推荐相关（一等公民，不是附属品）

- **Query Profile** — 一次推荐请求的输入：目标 User 的全部 CollectionEntry 列表。**每次请求都从数据源拉取**。
- **Learned Preference** — 系统从历史交互中**学习**到的用户偏好分布（题材/年份/标签权重）。与 Query Profile 不同：它是可缓存的模型产物。
- **Recommendation** — 一条推荐结果：`{ Subject, score, cold, popularity_rank }`。
- **Popularity Baseline（流行度基线）** — 按 Subject 聚合收藏数/评分排序的简单推荐。**这是所有算法的最低及格线**，打不过它的模型没有上线价值。
- **Franchise（系列）** — 同一部作品的不同季/续作/剧场版/番外组成的集合；判定依据是 Bangumi 条目关系（续作/前传/系列三种）。产品行为：已看系列的其余成员不进推荐，列表内每个系列至多一条。
- **Sequel（续作）** — 某作品的延续（下一季 / 续集 / 剧场版）。在"发现"定位下不算发现，被排除出候选。
- **冷门（Cold）** — 全局热度排名靠后（超出阈值）的 Subject；是"发现"定位的供给来源。
- **Cold Quota（冷门配额）** — 推荐列表内保证冷门条目的数量下限；是"发现"定位的落地机制。

## 对外契约

- **Recommendation API** — 系统的对外接口：`输入 username → 输出 Recommendation 列表`。无状态、版本化（`/v1/`）。前端只消费它，不参与任何计算。
